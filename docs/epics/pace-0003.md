## Summary

Update the repository workflow so planned work starts on an epic branch, ticket implementation branches are created from that epic branch, and completed ticket branches merge back into the epic before the epic lands on `main`.

## Goals

- Document the epic-and-ticket branch workflow.
- Add reusable epic and ticket planning templates.
- Validate pull request branch relationships in GitHub Actions.
- Keep `main` protected as the final integration branch for completed epics.

## Non-Goals

- No automated branch creation scripts in this epic.
- No changes to Conventional Commit title validation.
- No changes to release-please publishing behaviour.

## Architecture Notes

The branch-flow check is implemented as a GitHub Actions workflow so it runs where pull request base/head refs are authoritative. It validates branch names and required planning docs without adding runtime application code.

## Integration Plan

- Open this epic branch as a draft pull request into `main`.
- Branch ticket implementation from this epic branch.
- Merge completed ticket branches back into this epic branch.
- Mark the epic pull request ready for review after planned ticket work is merged.
