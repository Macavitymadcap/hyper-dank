## Summary

Extract the walking pace app into an app workspace, promote app-agnostic pieces into reusable
workspace packages, and add an ordered verification reporter so package and browser confidence can
be checked with one command.

## Goals

- Move the product app into `apps/walking-pace` without changing its Hono, HTMX, auth, or database behaviour.
- Extract reusable component, HTTP, and database primitives into `libs/components`, `libs/http`, and `libs/database`.
- Keep root scripts as the main maintainer entrypoint while allowing the app package to run its own local commands.
- Add consumer compatibility coverage for workspace packages.
- Add `bun run verify` as a fail-fast gate runner that writes a Markdown report.
- Update current docs so the workspace layout is discoverable.

## Non-Goals

- No package publishing to an external registry in this epic.
- No second production app or deployment target.
- No app redesign, auth model change, or new database backend.
- No replacement of the existing epic-and-ticket branch flow.

## Architecture Notes

The root package remains private and owns workspace orchestration. `apps/walking-pace` owns the
deployable app runtime, app-specific scripts, Vite config, public files, and domain code.
Reusable primitives move into private workspace packages with stable package names:

- `@macavitymadcap/hyper-dank-ui` for server-rendered JSX primitives and shared component CSS.
- `@macavitymadcap/hyper-dank-transport` for generic form parsing, route parameter, responder, and redirect helpers.
- `@macavitymadcap/hyper-dank-data` for database lifecycle, migration, and adapter-test primitives.

Root scripts continue to provide the normal maintainer workflow. Package build scripts emit
declarations for compatibility checks, and `e2e/consumer-compat` exercises package imports from a
consumer-style test frame.
