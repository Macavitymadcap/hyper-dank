## Summary

Restore the Railway-style Docker build after the automation workspace package was added to the app
dependency graph. The Docker install layers must include every workspace package manifest before
running frozen installs, otherwise clean remote builds can fail before the full source tree is
copied.

## Goals

- Include the automation package manifest in both Docker install stages.
- Copy the built automation package output into the runtime image with the other shared packages.
- Keep the hotfix limited to the Docker deployment path.

## Non-Goals

- No app runtime behaviour changes.
- No package API changes.
- No Railway configuration changes.
- No follow-on ticket branches under this hotfix epic.

## Architecture Notes

The Walking Pace app depends on the shared Hyper-Dank workspace packages, including
`@macavitymadcap/hyper-dank-automation`. The Dockerfile copies package manifests before
`bun install --frozen-lockfile` so Docker can cache dependency installation. Any workspace package
listed in the dependency graph must have its manifest present in that layer.
