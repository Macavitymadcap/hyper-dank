## Summary

Make the public npm package state easy to verify before and after each Hyper-Dank package release,
so maintainers can see whether local package versions have reached npm and can follow the same
staged-publishing process each time.

## Goals

- Compare local package versions against npm registry versions with a repeatable repo script.
- Make the script explain whether a release is needed and which packages are affected.
- Document the release process around the existing trusted publishing and staged npm workflow.
- Document how maintainers approve current staged packages and reject stale staged versions.
- Preserve the current lockstep package release model for `@macavitymadcap/hyper-dank-*` packages.

## Non-Goals

- No direct local `npm publish` command or token-based publishing path.
- No replacement for Release Please versioning or the GitHub Actions staged publishing workflow.
- No change to package APIs, export maps, or package version numbers.

## Architecture Notes

The release-state check should read the same package manifests that `check:publishing` validates,
query npm metadata without writing to the registry, and report only maintainer actions. The existing
`.github/workflows/publish-npm.yml` remains the publishing mechanism because it owns trusted
publishing, provenance, staged package approval, and skipping package versions that already exist on
npm. The maintainer runbook also needs to account for npm staged versions, because staged packages
are not visible as public `latest` but still occupy the package-version staging slot.

## Integration Plan

- Land the script and docs in the current package-publication follow-up branch.
- Run the check against npm before publishing `0.3.0`.
- Publish through the existing GitHub Actions workflow with
  `release_mode=stage-unpublished-packages`, or publish a Release Please GitHub release.
- Re-run the check after staged packages are approved on npm.
- Use `npm stage list <package>` to inspect pending stages before rerunning a failed workflow.
- Reject stale staged versions after the current lockstep package set has been approved.
