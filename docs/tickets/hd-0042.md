## Summary

Capture the maintainer steps learned during the first staged npm approval: staged package versions
can block later workflow runs even while npm `latest` still shows an older public version.

## Goals

- Add a durable npm release runbook for staged package approval.
- Explain how to list pending staged package ids.
- Explain when to approve current staged package versions.
- Explain when to reject stale staged package versions.
- Document `E409 Conflict` as a likely already-staged-version signal.

## Non-Goals

- No change to package versions, release tags, or Release Please configuration.
- No local publishing path.
- No automation for 2FA-backed approval or rejection.

- Use the runbook after each `Publish npm packages` workflow run.
- Approve staged versions that match `main`.
- Reject stale staged versions after the current lockstep package set is public.
