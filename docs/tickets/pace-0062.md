## Summary

Make the root README and package READMEs answer the practical adopter question: "Can Campaign
Ledger install this, and how?" If the packages are not published to npm, this ticket must choose and
prove another consumption route before downstream app work depends on Hyper-Dank.

## Goals

- Decide the Campaign Ledger installation route from the `pace-0061` audit: npm publication,
  GitHub Packages, GitHub release/package tarballs, or a deliberately temporary local-tarball flow.
- Implement or document the smallest viable package distribution step needed for that route.
- Test the selected route from outside the Hyper-Dank workspace using public package names and the
  same package manager flow Campaign Ledger will use.
- Update `README.md` with a concise adopter path for package status, installation, local pack
  scripts if still relevant, docs site, Storybook, and reference app.
- Update `libs/components/README.md`, `libs/database/README.md`, `libs/http/README.md`, and
  `libs/scripts/README.md` with install or consumption guidance based on the `pace-0061` audit.
- Document public import paths, CSS exports, subpath exports, peer dependencies, runtime
  assumptions, and package-owned versus app-owned responsibilities.
- Keep examples compact and aligned with public package exports and compatibility tests.

## Non-Goals

- No broad release automation beyond the minimum needed to make the selected route usable and
  repeatable.
- No generated API documentation; deeper API pages belong to `pace-0063`.
- No Storybook content rewrite beyond links to the relevant UI reference.
- No new package exports unless a README claim exposes a documented bug that must be corrected.

## Acceptance Criteria

- Root README states current package consumption status without overpromising unsupported external
  publication.
- Campaign Ledger has a tested installation path for the Hyper-Dank packages it needs.
- Each package README includes installation or local consumption guidance, import examples, public
  export summary, peer dependencies, and package boundaries.
- UI README explains `@macavitymadcap/hyper-dank-ui/styles.css` and browser asset expectations.
- Data, transport, automation, and automation/content guidance matches current export maps.
- README links send readers to the docs site, recipes, and Storybook where deeper reference lives.
- `bun run check` passes, and package builds are run if metadata or export examples changed.
- The selected install route is verified from outside the Hyper-Dank workspace.

## Assumptions

- `pace-0061` has accepted the source of truth for package status.
- If public npm publication is not selected, the chosen route must still be good enough for Campaign
  Ledger to start consuming Hyper-Dank deliberately.
