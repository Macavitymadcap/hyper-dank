## Summary

Create the public Hyper-Dank docs site at `/` so the repository explains the libraries, system
patterns, demo, Storybook, and adoption path without requiring readers to inspect source first.

## Goals

- Add a `site/` Jekyll source tree.
- Document the components, database, HTTP helpers, Hono/HTMX framework pattern, verification flow,
  Walking Pace demo, Storybook, and Character Sheet handoff.
- Use GitHub Pages repository-path base URL support for `/hyper-dank`.
- Keep generated docs static and easy to review.

## Non-Goals

- No custom Jekyll plugin dependency.
- No external registry publication docs beyond current workspace consumption.
- No replacement for detailed source-level architecture docs.

## Implementation

- Add `_config.yml`, layout CSS, navigation, and docs pages under `site/`.
- Link `/pace/` and `/storybook/` from the docs navigation.
- Keep pages Markdown-first so GitHub Pages can build them with the standard action.

## Tests First

- Run `bun run check`.
- Let the Pages workflow build Jekyll with `actions/jekyll-build-pages`.

## Acceptance Criteria

- The docs home explains Hyper-Dank as the primary project.
- Library, system, demo, Storybook, verification, and Character Sheet adoption pages are linked from
  the site.
