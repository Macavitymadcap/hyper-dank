## Summary

Extend consumer compatibility coverage so Hyper-Dank packages are tested against Character
Sheet-style markup and generic blog, dashboard, static demo, and server-app compositions.

## Goals

- Keep Character Sheet as the flagship consumer scenario.
- Add representative package-import smoke tests for static blogs, dashboards/admin tools, and
  static/demo pages.
- Include `@macavitymadcap/hyper-dank-automation` in package compatibility where useful without
  requiring live GitHub or browser services.
- Ensure package READMEs and exports match what the compatibility tests import.

## Non-Goals

- No direct Character Sheet package migration.
- No exhaustive visual regression suite.
- No external package registry publication.

## Compatibility Scenarios

| Scenario | Expected Coverage |
| --- | --- |
| Character Sheet | Tabs, panels, forms, key-value/stat surfaces, notices, and dense page composition |
| Static blog | Page shell, article/list layout, navigation, metadata, and static CSS import |
| Dashboard/admin | Cards/panels, status summaries, tables/lists, action bars, and filters |
| Static demo | Lightweight page shell, form feedback, local data display, and no server-only assumptions |
| Script consumer | Import process/GitHub/report helpers without app-specific paths |
