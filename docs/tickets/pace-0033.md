## Summary

Broaden `@macavitymadcap/hyper-dank-components` so future Hyper-Dank apps can compose common server
app, blog, dashboard, and Character Sheet surfaces without copying app-specific component code.

## Goals

- Add reusable primitives for layout/navigation, richer forms, data display, and feedback states.
- Keep component names generic and semantic rather than app-domain specific.
- Export new components and types through the package root with CSS class contracts and tests.
- Add Storybook coverage for representative blog, dashboard, static-demo, and Character Sheet-like
  compositions.
- Fold in the shared walk-history table sizing polish identified during `pace-0032` discovery so
  mixed-content tables balance cleanly on both desktop and mobile layouts.

## Non-Goals

- No Character Sheet runtime import migration.
- No app-specific organisms such as character stat blocks, walk tables, or blog post renderers.
- No visual redesign of Walking Pace.

## Discovery Follow-on

This ticket also owns a narrow refinement to the existing shared `ScrollableTable` primitive:

- add an additive column-sizing surface so consumers can express desktop and mobile widths per
  column without replacing the semantic table shell
- retune the Walking Pace walk-history table and static demo to use the new sizing surface
- keep date/time cells readable as a stable two-line block and preserve enough width for compact
  action buttons across desktop and mobile viewports
