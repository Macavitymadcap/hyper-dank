## Summary

Improve the existing shared UI atoms and add the accepted core action, form, and icon primitives
from the app-builder readiness audit so server apps, dashboards, static blogs, and demos have a
stronger first layer of reusable HTML-first components.

## Goals

- Improve existing atoms and form primitives: `Button`, `FormField`, `InputGroup`, `Switch`,
  `Icon`, `Badge`, `Chip`, `Card`, `Panel`, and `TableCell`.
- Add accepted core primitives: `LinkButton`, `IconButton`, `ButtonGroup`, `SegmentedControl`,
  `TextareaField`, `SelectField`, `CheckboxField`, `RadioGroup`, `Fieldset`, and
  `ValidationSummary`.
- Expand the curated inline icon catalogue for common docs, admin, blog, dashboard, demo, and
  app-neutral tabletop-adjacent concepts.
- Keep components native-first, HTMX-friendly where useful, and graceful without JavaScript or HTMX.
- Add or update exports, tests, Storybook stories, CSS hooks, README notes, and compatibility
  coverage for the new public API.

## Non-Goals

- No layout, navigation, dialog, feedback, data-display, or content primitives from `pace-0053`.
- No toast/snackbar, tooltip, date picker, autocomplete, data grid, tree view, chart, or rich text
  editor work.
- No Walking Pace product redesign beyond adapting it safely to changed shared primitives.
- No external icon dependency unless the implementation proves the curated inline catalogue is not
  viable and updates the epic first.

## Rollout Notes

- Keep new components small and native-first; no hidden client state or SPA-style behaviour.
- Components should accept HTMX props where server-rendered interaction is natural, but must keep
  native fallbacks.
- Avoid app-specific nouns in component names, props, stories, tests, and docs.
- If this ticket becomes too large after tests are written, split along the milestone boundaries
  before implementation continues.

## Implementation Notes

- Added core action primitives: `LinkButton`, `IconButton`, and `ButtonGroup`.
- Added core form primitives: `TextareaField`, `SelectField`, `CheckboxField`, `RadioGroup`,
  `Fieldset`, `SegmentedControl`, and `ValidationSummary`.
- Improved existing `FormField` and `InputGroup` accessibility wiring for help text, error text,
  `aria-describedby`, and invalid states.
- Expanded the inline `Icon` catalogue and alias map for docs, admin, dashboard, blog, demo, and
  app-neutral tabletop-adjacent uses.
- Added public exports, render tests, CSS hooks, package README coverage, and Storybook references
  for the new and shared primitives.
