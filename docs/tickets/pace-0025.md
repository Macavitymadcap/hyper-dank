## Summary

Add a browser-only Walking Pace demo that can be published at `/pace/` from GitHub Pages and still
feel like a real working example.

## Goals

- Persist demo walks in `localStorage` under `hyper-dank:pace-demo:walks:v1`.
- Reuse existing pace validation, pace math, app styling, and shared component CSS contracts.
- Support add, delete one, clear all, invalid input messages, reload persistence, and invalid stored
  data recovery.
- Build with Vite and support GitHub Pages base paths.

## Non-Goals

- No auth, admin, invitations, user limits, or server-owned sessions.
- No server mutation endpoints for `/walks`, `/stats`, or auth routes.
- No replacement of the authenticated Hono template app.

## Implementation

- Add a static demo Vite entry with a localStorage-backed provider and DOM rendering layer.
- Add a dedicated `build:demo` script.
- Add unit tests for provider behaviour and a browser smoke script for `/pace/`.
- Keep static demo code isolated from server route classes.

## Tests First

- Storage tests cover empty storage, invalid JSON, schema recovery, add/delete/clear, stats, and
  reload persistence.
- Browser smoke proves `/pace/` can add and clear walks without calling server mutation endpoints.

## Acceptance Criteria

- `bun run build:demo` emits a static demo.
- `bun run test:static-demo` passes.
- The demo remains usable under `/pace/` and `/hyper-dank/pace/`.
