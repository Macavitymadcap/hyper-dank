## Summary

Expand `@macavitymadcap/hyper-dank-transport` and
`@macavitymadcap/hyper-dank-automation` so app builders can reuse the repeated mechanics that now
show up across route handlers, HTMX forms, local app servers, screenshots, a11y checks,
verification gates, and static-site smoke tests.

The shared packages should own mechanics, not product knowledge. Consuming apps still own route
paths, auth fixtures, seeded users, permissions, smoke journeys, screenshot states, deployment
targets, and product copy.

## Goals

- Improve `@macavitymadcap/hyper-dank-transport` with small Hono/HTMX helpers for route responses,
  form submissions, validation/error handling, request classification, and safe form value reads.
- Expand `@macavitymadcap/hyper-dank-automation` with reusable local server harness helpers,
  screenshot/a11y target catalogues, static-site smoke helpers, verification gate presets or
  builders, and clearer browser-flow composition.
- Lift app-neutral mechanics from `apps/walking-pace/scripts/lib/app-server.ts`,
  `screenshot-flows.ts`, `test-static-demo.ts`, `test-a11y.ts`, `verify.ts`, and related scripts
  only where they can be reused without route or fixture leakage.
- Keep Walking Pace-specific auth setup, seeded users, sample walks, route paths, and screenshot
  flow definitions app-local.
- Update package exports, README coverage, public docs references, and consumer compatibility tests
  for the new helper APIs.

## Non-Goals

- No auth framework, permission framework, router abstraction, Hono replacement, or hidden route
  lifecycle.
- No app-owned route names, fixtures, users, screenshots, smoke journeys, or deployment policy in
  shared packages.
- No broad rewrite of the Walking Pace app routes or scripts beyond adopting small shared helpers
  where that proves the package contracts.
- No Playwright test framework replacement; helpers should compose with Playwright rather than hide
  it.
- No visual screenshot refresh unless an implementation change affects the screenshot script output.
- No breaking changes to existing transport or automation exports.

## Public API Requirements

- Additive exports from `@macavitymadcap/hyper-dank-transport` and
  `@macavitymadcap/hyper-dank-automation`.
- Existing `FormValues`, `errorMessage`, `routeParam`, `HttpResponder`, `startBunServer`,
  `waitForHttp`, `captureScreenshots`, `runPa11y`, `runVerification`, and PR image helpers remain
  backwards compatible.
- Helper names must describe mechanics, not product flows: request, response, form, fragment,
  redirect, server, target, screenshot, a11y, static artifact, verification gate.
- Shared helpers must accept app-provided renderers, route paths, auth cookie functions, target
  lists, and setup callbacks rather than embedding product fixtures.
- Package READMEs and public docs must include full descriptions for functions, types, parameters,
  return values, errors, and examples.
- Consumer compatibility must import representative new exports through packaged public boundaries.

## Candidate Interfaces

The exact names may change during implementation, but the ticket should stay within this boundary:

- Transport:
  - `isHtmxRequest(context | headers)` or a headers-first helper under `HttpResponder`.
  - `FormValues.number()`, `FormValues.boolean()`, `FormValues.optionalString()`, or narrow helpers
    if tests prove they reduce repeated route parsing without hiding validation.
  - `createFormErrorResponse()` or `respondWithFormErrors()` helpers that accept app-owned render
    callbacks.
  - `fragmentOrPage()` / `htmlFragmentResponse()` style helpers that choose HTMX fragments versus
    full page responses without owning route names.
- Automation:
  - `createAppServerHarness()` or extensions to `startBunServer()` for setup/teardown and readiness
    checks.
  - `ScreenshotTarget`, `ScreenshotTargetGroup`, and summary helpers that complement existing
    screenshot flow capture.
  - `A11yTarget` and `runPa11yTargets()` for named target lists with optional auth cookies/configs.
  - `assertStaticArtifact()` / `smokeStaticSite()` helpers for static HTML directories.
  - `createVerificationGate()` / gate builders for common command checks while keeping command
    lists app-owned.

Avoid abstractions that hide Hono `Context`, Playwright `Page`, Pa11y options, or Bun server
handles from app scripts that need them.

## Implementation Notes

- Start with tests in `libs/http/src` and `libs/scripts/src` before adopting helpers in app scripts.
- Prefer pure helpers, typed options, and explicit callbacks over broad framework classes.
- Keep fixture-rich app helpers such as local auth users, sample walks, and product screenshot
  states in `apps/walking-pace`.
- Update app scripts only where the shared helper improves clarity or proves the public contract.
- Do not add new package dependencies unless the implementation proves they are needed and records
  the package impact in the PR.
