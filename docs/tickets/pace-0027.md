## Summary

Replace this repository's active Railway production deployment path with a GitHub Pages workflow that
publishes Jekyll docs, the static Walking Pace demo, and Storybook as one artifact. Keep the
Railway-compatible server deployment scripts and runbook available for downstream Hyper-Dank apps,
including Character Sheet.

## Goals

- Publish docs at `/`, the static demo at `/pace/`, and Storybook at `/storybook/`.
- Build Pages assets on pushes to `main` and via manual workflow dispatch.
- Remove only the active Railway deployment workflow/config for this repository.
- Preserve Railway-compatible server deployment docs, Docker support, and scripts for downstream
  apps.
- Preserve CI verification separately from deployment.

## Non-Goals

- No server production deployment in this ticket.
- No removal of the server app, Dockerfile, `bun run start`, `bun run db:migrate`, `bun run
  seed:admin`, or `/healthz` support.
- No claim that Character Sheet or other downstream Hyper-Dank apps should avoid Railway.
- No database migration or seed workflow in production.
- No Storybook visual-regression service integration.

## Implementation

- Replace `.github/workflows/deploy.yml` with a Pages deployment workflow.
- Build the pace demo and Storybook before uploading the Pages artifact.
- Use `actions/jekyll-build-pages`, `actions/upload-pages-artifact`, and
  `actions/deploy-pages`.
- Remove root `railway.json` because this repository no longer has an active Railway deployment.
- Add or keep Railway runbook/example configuration outside the active root deployment config so
  downstream server apps can use the same Bun scripts and Dockerfile pattern.

## Tests First

- Run `bun run build:demo`.
- Run `bun run storybook:build`.
- Run the Pages artifact preparation script locally where possible.
- CI validates the full deploy build on `main`.

## Acceptance Criteria

- The production workflow no longer requires Railway secrets.
- A Pages artifact contains `index.html`, `pace/index.html`, and `storybook/index.html`.
- README and architecture docs describe Pages as production.
- README and deployment docs still describe the Railway-compatible server deployment pattern for
  Character Sheet-style consumers.
