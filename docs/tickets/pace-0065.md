## Summary

Make the docs site easier to travel through. Libraries and recipes should have comparable structure,
the left-hand navigation should help readers understand the package map, and responsive/sidebar
behaviour should remain accessible on desktop and mobile.

## Goals

- Improve the libraries navigation so UI, data, transport, automation, and content pages are easy
  to scan from a persistent left-hand area where the layout supports it.
- Add accessible expand/collapse behaviour for library navigation if the audit accepts it.
- Rework recipes so each one names all required Hyper-Dank packages, app-owned responsibilities,
  verification suggestions, and links to package API docs and Storybook.
- Keep docs-site pages task-oriented and avoid duplicating full README or Storybook content.
- Check responsive layout, keyboard navigation, focus order, and light/dark theme behaviour.

## Non-Goals

- No full redesign or marketing landing page.
- No new recipe shapes beyond those accepted by `pace-0061` unless they are needed to fix a clear
  docs gap.
- No Storybook component docs rewrite; that belongs to `pace-0064`.
- No new shared UI components for the docs site unless an existing primitive can be reused safely.

## Acceptance Criteria

- Library docs are discoverable from an accessible, responsive navigation pattern.
- Recipes list all required Hyper-Dank packages and app-owned responsibilities.
- Cross-links connect README/package docs, library API pages, recipes, Storybook, and verification
  guidance.
- Docs navigation works with keyboard and remains usable on mobile and desktop.
- Docs build, a11y checks, and relevant screenshots pass before the ticket is ready.

## Assumptions

- `pace-0063` has established the final library page set and API reference shape.
- The docs site should remain a static Pages artifact and avoid heavy client-side navigation code.

## Implementation Notes

- Added a shared `docs-layout`, `docs-side-nav`, and `docs-page` styling layer so library and
  recipe pages use the same responsive disclosure navigation pattern without new client-side code.
- Made the open desktop side navigation stretch with the page column while closed disclosures
  collapse back to their summary height.
- Added mobile drawer behaviour: docs side navs start as a thin fixed left rail, then open over the
  page instead of pushing content down.
- Reworked recipes into navigable sections with required package lists, app-owned responsibilities,
  verification notes, examples, and links to package API docs, Storybook, demo, and verification
  guidance.
- Updated the library pages to opt into the shared docs side-nav hook while keeping their existing
  library-specific current-page links.
- Added docs build and public-docs coverage for library navigation structure and complete recipe
  sections so regressions fail before publication.
