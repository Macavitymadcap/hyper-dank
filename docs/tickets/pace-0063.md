## Summary

Make the docs site a real API reference for Hyper-Dank libraries. The ticket should document
exported helpers, types, classes, variables, parameters, return values, errors, and examples, while
adding lightweight checks that keep docs references aligned with public package exports.

## Goals

- Expand library pages for `@macavitymadcap/hyper-dank-ui`,
  `@macavitymadcap/hyper-dank-data`, `@macavitymadcap/hyper-dank-transport`,
  `@macavitymadcap/hyper-dank-automation`, and `@macavitymadcap/hyper-dank-automation/content`.
- Use Storybook as the canonical rendered UI reference while keeping the UI docs page useful for
  package setup, CSS export, component groups, and links to component stories.
- Add JSDoc-style descriptions for non-UI helpers, public types, parameters, return values, thrown
  errors, side effects, examples, and known limits.
- Add a docs consistency check for stale export names, broken internal links, and public/private
  boundary leaks where practical.

## Non-Goals

- No automatic TypeScript documentation generator unless the implementation proves a small local
  script is simpler than maintained Markdown.
- No broad Storybook docs rewrite; that belongs to `pace-0064`.
- No new runtime helpers or public package APIs unless required to correct a documented mismatch.
- No package publication changes.

## Acceptance Criteria

- Library pages document the public API for UI, data, transport, automation, and content helpers.
- Non-UI helpers include clear descriptions, parameters, return values, errors, examples, and
  limitations.
- UI docs explain package setup and component groups, then link to Storybook for rendered component
  detail.
- A repeatable check or documented manual gate catches stale exports, broken links, and boundary
  leaks at a useful level of confidence.
- `bun run check` and relevant docs/package checks pass.

## Assumptions

- The `pace-0061` audit has defined the accepted docs coverage map.
- Hand-maintained Markdown is acceptable for this epic unless a lightweight generator is clearly
  cheaper and less brittle.
